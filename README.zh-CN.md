# AutoParking — ETS2LA V3 自动泊车第三方插件

在**平面地图**上选一个车位，插件把车位用 **AR 叠加层**画到游戏画面里，然后自动完成
**前进 / 倒车 / 换挡（自动挡）/ 刹车 / 转向**，把车头停进去。

> **当前状态：M4 实车闭环验证中。** 规划器与控制器已离线验证（见下文「自检工具」），换挡指令也确认
> 能进游戏。**踏板那半问题的根因是通路不是调参**：我们的油门/刹车值走宿主配置的那条分发路径，打开宿主的
> **设置 → 实验 → Enable Memory Output for Pedals** 之后就能落地（这条是驾驶者实车反馈；日志现在会打印
> 当时用的是哪条通路，所以下一次跑就能确定长倒库段约 0.5 km/h 的爬行是不是同一个原因）。仍未收口的两件：
> 在那条通路上**哪个回显字段**能证明指令进了游戏（`user_brake` 是在旧通路上验的），以及泊车期间与我们
> 刹车做加权平均、把气压耗光的那个**对手通道到底是谁**。读法见「故障排查」。
>
> **只做牵引车头，不支持挂车**（带挂车时默认拒绝启动）。

## 1. 安装

1. 编译：
   ```
   dotnet build -c Release
   ```
   产物是单个 `AutoParking.dll`。
2. 把它放进 ETS2LA 的插件目录：
   ```
   <ETS2LA 安装目录>\current\Plugins\AutoParking.dll
   ```
   如果同一个工作区里也有便携版主程序，那它就是 `.csproj` 的 HintPath 指向的同一棵 `current\`：
   相对仓库根为 `..\..\ETS2LA-win-release-Portable\current\Plugins\`（见 `AGENTS.md`）。
3. **重启 ETS2LA**（插件是影子复制加载的，热重载不可靠）。
4. **打开宿主的 设置 → 实验 → Enable Memory Output for Pedals** 再跑泊车。不开时宿主把我们的油门/刹车
   写进旧版虚拟手柄那块内存，那正是我们踏板指令丢失的地方；插件的状态表和日志会打印实际用的是哪条通路
   （`transport=memory|legacy`）。宿主自己注明这条路并非在所有机器上都起效，而且改动后可能需要重启游戏。

依赖：插件直接引用 `current\` 下的 `ETS2LA.*.dll` 与 `TruckLib*.dll`、`Hexa.NET.ImGui.dll`，
所以**必须和 ETS2LA 主程序放在同一安装目录树里**。`.csproj` 里这些引用都是 `Private=false`，
不会把宿主 DLL 拷进插件目录。踏板通路那一行要调 `ETS2LA.Game.GameSettings`，因此宿主至少得是
2026-09-29 `5299cc9` 之后的构建；更老的宿主能加载插件，但渲染那一行（或那条探针）时会抛异常。

## 2. 打开设置页与地图

- 设置页路由（按约定自动被发现，无需注册）：`/plugins/adjustments/local.autoparking`
  即 设置 → 调整 → **Auto Parking**。
- 两个可视化窗口由设置页开关控制：
  - **平面地图**（ImGui 窗口，默认开）：显示道路车道线、 prefab 边/导航曲线、障碍物、当前路径，
    外加静态图层——**凡是有地面几何的地图条目类都画**：品红=建筑线段、黄绿=散落模型点（路灯/杆/集装箱）、
    蓝紫=牌、青=区域环（车流区/地图块/触发区）、灰=其他所有条目（先看见，再叫出它的名字）。
    实心表示地图格式自己的碰撞标志为真，空心为假。
    只跳过三类：道路、地形块、compound 自身的节点（它就在刚画出来的那堆孩子上面），理由写在 `MapGeometry.cs`。
    **这一层现在只是画出来给人看，还不拦路**（先测量、再显示、最后进规划，原因见 6.4；
    上限写在 `MapGeometry.cs`）。能不能画出东西取决于宿主的**数据保真度**：建筑要 Medium，
    模型点要 High。「地图数据」状态行末尾带着计数（`静态 N 项 / 场站轮廓 M`）。
    沙色细框是 **prefab 轮廓，取的是它控制点的凸包**——地图数据里 prefab 只发布控制节点，别的外框拿不到。
    它是参考不是障碍（车位通常就在被描的那个轮廓里面），对 L 形/环形构件明显高估，两个控制点的 prefab
    连多边形都形不成。设计文档 §31 记了它在真实场区跑出来的样子：全是路口构件，不是车前那堆箱子。
    按钮行末尾是**「锁定窗口」勾选框**：勾上时窗口位置和大小被冻住（`ImGuiWindowFlags.NoMove | NoResize`），
    这是让选位手势确定的前提，原因见第 8 节。默认不勾，因为窗口本来就需要偶尔挪开。
  - **AR 叠加层**（游戏画面上，默认开）：车位框、车身投影、前进方向箭头、目标位姿，外加
    **路线预览**——动手之前就把"将要占用的走廊 + 将要走的中心线 + 换挡点"画在车前地面上（见 6.7）。

## 3. 绑定热键（必须）

覆盖层和游戏是两个应用。**SCS SDK 在游戏失焦时不接受输入**，所以启停不能用网页按钮，
必须用游戏内热键：

| 控件 ID | 作用 |
|---|---|
| `local.autoparking.Toggle` | 空闲→开始；运行中→暂停；已暂停→继续 |
| `local.autoparking.Abort` | 立即刹停、释放控制通道、交还辅助驾驶 |

绑定位置：**设置 → 控制**（插件在 `Init()` 里注册控件，因此启动后就能在列表里看到，
不需要先启用插件）。

注意这里的不对称：上面那条失焦规则说的是**输入**，宿主的任何设置都改不了它。**输出**是另一半——
开了 `Enable Memory Output for Pedals` 之后，我们的踏板指令在失焦时也照样进得去。这等于拆掉了一层
意外的安全垫：以前鼠标切到地图窗口，踏板权限会立刻失效，现在不会了。`Abort` 必须绑好、手要能碰到。

## 4. 使用流程

1. 把车开到车位附近（路径长度上限见 `MaxTakeoverDistanceM`）。
2. 在平面地图上点选/调整目标位姿，或用「保存的车位」记忆上一次的位置。
   点击只放下车位并沿用当前车头朝向；**要定朝向就按住往外拖出那个圈**——圈（约 12 px）以内不算方向，
   因为旋转中心就在光标底下，一两个像素的抖动本会随机挑一个角度。
   **在画布边缘附近选位前，先勾上「锁定窗口」**——在那里对地图按下同时也是对窗口边框按下，窗口一旦被
   拖着走，量的就是窗口移动而不是手的转向（见第 8 节）。
   AR 叠加层会同步画出车位，用来确认地图坐标和游戏里的实际位置对齐。
3. 想先看效果就保持 **Dry-run 打开**：所有控制量只计算、只显示，不发进游戏。
4. 关掉 Dry-run，回游戏画面，按 `Toggle` 热键开始。
5. 需要接管就再按一次 `Toggle` 暂停；`Abort` 直接放弃并交还车辆。

启动会被拒绝的情况（状态表和日志都会写明原因）：还没选车位 / 遥测超时 / SDK 未激活或
游戏暂停 / 挂着挂车 / 地图数据未就绪 / 路径无解或存在障碍冲突 / 路径过长。

## 6. 自检工具

### 6.1 规划几何自检（设置页「运行规划自检」）
24 组固定起终点（直线对齐、90° 垂直入库、45° 斜入库、侧方平移、不可达等），
断言：解的存在性、段数 ≤ 4、采样连续（相邻点 ≤ 0.35 m）、终点位姿误差 < 1e-3、
无 NaN、曲率不超规划半径、路径不许多绕一整圈、障碍冲突必须被拒。
不需要游戏在跑。结果写日志 + 设置页状态行。当前 **24/24**。

### 6.2 指令通路自检（设置页「测试挂 D / 测试挂 R」）
油门/刹车走的是**模拟轴**，换挡/手刹走的是**布尔动作**——两条不同的代码路径。
在未启用车库且关掉 Dry-run 时按这两个按钮，然后看状态表「人工输入」行尾部的
`gear=实际/仪表 shifter=变速箱类型` 有没有变号。
这能在 2 秒内回答"布尔动作到底进不进得去游戏"，不用跑完一整个泊车位。

### 6.3 离线闭环仿真（`Tools\PlannerHarness`）
自行车模型驱动真实的 `Follower`，输出横向/航向误差、换挡脉冲数，以及转向质量指标
（满舵时长、方向盘换向次数、方向盘总行程）。具名用例每一个都是为了钉住一个只有逐 tick 才看得见的 bug：
**挡箱失聪**（脉冲永不接合，必须降级为"继续行驶并补发"而不是死等）、**中途冒出障碍**（关掉重规划会停等到
超时，打开则从当前位姿重算并到位）、**停稳退空挡的自动箱**（挡位确认必须接受仪表盘读数，否则一次挂挡
烧出 110 个脉冲）、**两段式路线**（唯一多段路径，曾经带着冻结的 `剩` 直接倒穿终点）、**刹不住冲过
预热点**（不许把方向盘钉在追一个已经落到身后的视点上），以及一个合成的**距离退行**序列——闭环里
已经没有自然触发场景，就用合成状态喂出"距终点变大"，确保那段"停车重排二段修正"的保险真的被执行过。
它自己是一个控制台工程：

```
dotnet run --project Tools/PlannerHarness -c Release
```

放在 `Tools\` 下，插件 `.csproj` 用 `DefaultItemExcludes` 把这个目录整个挖掉——否则默认 globbing
会把它直接编进发布的 DLL。它按 `<Compile Include>` 链接纯数学子集，而不是引用插件工程，所以
不需要游戏、也不需要宿主 DLL，单独 clone 本仓库就能跑。

### 6.4 地图内容清单（设置页的「地图清单」按钮）
只读测量：以车为中心的采样圆里到底站着些什么，按地图条目类型分桶——数量、其中带地图格式碰撞标志的
有几个、最近的一个在多少米外、最高频的模型/方案 token，以及**去重后一共有多少种 token**。地图窗口和
状态表「地图内容」行只显示一行摘要；按钮把最多 8 类明细（标签 `[[地图清单]]`）连同采样中心、半径、
节点数、构建毫秒、宿主保真度写进日志。

同一个按钮接着还会在后台线程跑一次**全图清点**（标签 `[[全图清点]]`）：把整张已解析地图的所有条目按类型数一遍，带用时。
它抍开的是两个在屏幕上长得一模一样、修法完全不同的诊断："这个类根本不在数据里" vs "我们的节点遍历没走到它"。

打包成 `Compound` 的道具——成堆木托盘、集装箱、配电箱——也会被下钻遍历，并在明细里标成 `内含 N`：
compound 把孩子只存在**它自己的**字典里，对地图的节点索引来说一整堆东西就是**一个**条目（设计文档 §28）。
不钻进去，一个堆满货的场区会读起来像空的。

这些东西现在还不拦路，是故意的。静态障碍是下一步，而那里的分类规则必须来自真实车位会打印出什么
token 名，不是靠猜。token 种类数本身就是要量的一个数：上游的可视化插件正是因为"每个 token 解析一次
模型描述文件，首次启动卡约 20 秒"（`official-plugins\Plugins\VisualizationSockets\VisualizationSockets.cs:226`）
把 Model 分支整个关掉了。

注意：哪些类型能进 `MapData` 由宿主的**数据保真度**（`DataSettings.json`）决定，而且过滤发生在地图
*解析*时——建筑、牌子在 Medium 就保留；路灯等散落模型要 **High**；公司/城市 POI 区域要 **Extreme**。
改这个值得重新解析（重启），不是运行中能调的旋钮。

### 6.5 离线扇区读数（`Tools\MapSectorDump`）
问的是 6.4 同一个问题——"那儿到底有什么"——但直接从游戏的 `.scs` 里读，不用开游戏。它把 `.mbd` 和目标
坐标所在的**那一个**扇区按挂载顺序从所有归档里暂存出来（base 提供地图，DLC 会往同一个目录里加扇区却
**不带自己的 .mbd**），再用插件自己的 `MapItemSurface` / `MapItemProbe` 分类，所以离线读数和游戏里的
地图清单不可能各说各话。

```
dotnet run --project Tools/MapSectorDump -c Release -- <游戏目录或某个 .scs> [x z 半径]
```

写任何障碍分类规则之前先跑它：区分"不在地图数据里"、"在数据里但拿不到（prefab 自带几何）"、
"拿得到但只是画在画面外"这三种情况，这是唯一的便宜办法。设计文档 §30 记了它第一次跑出来的结果。

### 6.6 候选路线代价（日志里的 `路径代价` 块）

每次规划都会把**所有**候选路线打出来，不只是选中的那条：长度、换挡次数、这条路线**要求占用的地面**
（就是障碍判定已经在用的那个包络，沿路径扫过再按 1 m 栅格计数，所以来回压过的地面只算一次），
以及其中有多少压在"地图没担保过"的地面上。「担保」的意思：在采样半径内、离某条 prefab 导航曲线或
车道线不超过**可信走廊半宽**、且不在可碰撞条目底下。它只是测量，不是否决——选路仍然按长度加换挡罚，
而 harness 有一条断言保证挂上这张担保图不会改变结果（`仪表不改变选路`）。地图上的路线摘要现在写着
`占地 A m²（未确认 B m²）`。设计文档 §34 说明了为什么在 prefab 内部几何拿不到之后（§32），值得最小化的
是"侵入未确认地面"，并记下实测候选表：同一个场景里"绕一圈"那族在两个轴上都更差
（67.1 m / 339 m² / 未确认 194 m²），而选中的紧凑倒库是 49.1 m / 261 m² / 154 m²。
**离线数字已实测；游戏里的读数还没测。**

### 6.7 游戏画面里的路线预览（AR）

一旦有了路径，AR 就在**动手之前**把它画在地面上：车辆将要占用的走廊、走廊中心线，以及换挡处的
**洋红实心圆**（地图窗口里同一个决定用同一个色）。前进段青色、倒车段橙色——和平面地图用同一组色相，所以地上的段和地图上的段一眼就是同一条。
走廊宽度取 `RouteFootprint.EnvelopeSize().WidthM`，也就是障碍判定用来拦的那个包络、6.6 用来计数的
那个包络，所以**你看到的、拦你路线的、日志里统计的**不可能是三辆车。

画法是每挡位段一次 `Draw3DLineWithGradient(left[], right[])` 批量带状 + 一条每 1.5 m 取点的中心线
（`DrawStepM`）；**每个位姿对填一块多边形的做法被实车反馈 AR 太重**，所以换成 lane assist 那种形状。
还没有规划结果时，仍然画 M1 那条"自车→车位"的直线（每 5 m 一道横杠）：它回答的是"地图坐标和游戏里的
位置对不对得齐"，这件事预览在没路径时答不了。 **已实测：旧的逐段填充画法太重。未实测：现在这版的开销与观感。**

## 8. 故障排查

日志位置：`<安装目录>\current\ets2la.log`，搜 `AutoParking`。

**关键：本插件没有自动中止。** 按需求，除热键外任何观测都不终止动作；唯一的自动干预是
超速时的"踏板+手刹"。失控只能靠 `Abort` 热键，调试时手要放在键上。

几条例志的含义：

| 日志 | 说明 |
|---|---|
| `engaged: … · 换挡 N · 冲突 0, dry-run=…` | 已接受任务并开始跟随 |
| `start rejected: …` | 被 §4 的哪一条拒绝 |
| `制动探针 transport=memory sent_accel=-0.50 … user_brake=0.50` | 宿主这次用的哪条踏板通路 + 我们发布的带符号值 + 游戏回执。在 `legacy` 通路上，`sent_accel` 为负应当看到 `user_brake` 上升、`user_throttle` 为 0；**这个对应关系在 `memory` 通路上还没重测**，所以先信 `air=`（它与通路无关） |
| `挡位探针 请求=Reverse → gear=0 dash=-1 … shifter_type=…` | 每次发换挡脉冲记一行，带发出请求的阶段。`shifter_type` 决定这辆车认不认 `gear_drive/gear_reverse`。**`gear=0` 而 `dash=-1` 是正常现象**：自动箱每次停稳都会退回空挡，所以确认两个读数任一符合即算成功；这里出现脉冲风暴说明该锁存失效 |
| `控件已注册（…Toggle / .Abort）` | 启动时一行；没有它就说明 `Init()` 没跑到 |
| `[[地图清单]] 中心=… 半径=… 节点=… 条目=… 构建=… ms 宿主保真度=…` | 6.4 的地图内容清单，只有按下按钮时才打印；紧跟其后的缩进行每一行是一个类型 |

七条现场观察，各自都对应一个真 bug 或真限制，以及找出它的那个读数——证据链都记在
`docs\2026-09-30-autoparking-design.md` §17–§32：

- **踏板完全没反应（或一点击覆盖层就失效）** → 看制动探针的 `transport=` 与状态表「踏板通路」行。
  `legacy` 表示宿主把我们的油门/刹车写进旧版虚拟手柄那块内存，那里失焦的输入会被整个丢掉；`memory`
  表示直接写内存，失焦也生效。打开宿主的 **设置 → 实验 → Enable Memory Output for Pedals**——我们的
  踏板问题就是在这里解决的，跟 PID 无关。它并非在所有机器上都起效。
- **踩刹车没反应、车一直动** → 看 `air=` 与 `brake_temp=`。ETS2 的行车制动走气路，`air≈0` 时踏板值
  物理无效。长时间对抗别的通道压着的油门会把气耗光，所以状态表有「制动能力」行，且路线最后 2 m 内
  会改用驻车制动（另一条回路）停车。
- **`剩` 不再变小**（或者车明显倒穿终点了、界面还显示 12 m） → 弧长投影被钉住了。看制动探针里的
  `剩 / 横 / 航向差`：如果误差一直接近 0 而车已经离线，那是锚点过期，不是转向律的问题。
- **方向盘不动** → 先确认这一段是不是直线。直线倒库段 `steer=0` 是正确输出；只有当 `横` 同时不为 0
  才算故障（那就是上面那种锚点过期）。
- **车位朝向乱来** → 朝向取的是**拖出死区圈之后**的方向：点击那一刻旋转中心就在光标底下，以前一两个
  像素就足以选出一个任意角度。另一半是窗口本身：画布只离窗口边框 8 px，而 ImGui 的窗口**从边框任意处
  都能抓住**，所以在地图边缘按下会把整个窗口拖着走，而投影每帧重算，车位于是从拖动里滑走。
  选位时勾上地图窗口按钮行末尾的**「锁定窗口」**，要挪窗口时再取消。两次前踩过都记在这里免得重来：
  常驻 `NoResize` 没关掉这条路径（日志显示窗口仍然 1:1 跟着鼠标），常驻锁定又被否掉（窗口确实要挪）。
  `选位开始 / 选位结束` 两行日志给出拖动半径、这期间地图滑了多少像素、画布位移多少、当时锁没锁——
  开着锁选一次、关着锁选一次就是全部测试，锁定状态下 `画布位移` 必须是 0。**故障已实测，修法尚未实测。**
- **换挡脉冲以约 1 Hz 反复** → 自动箱停稳退空挡是正常的，确认必须接受仪表盘读数；出现脉冲风暴说明没接受。
- **地图上没有建筑、路灯、POI，而道路画得好好的** → 宿主在**解析地图时**就按**数据保真度**
  （`DataSettings.json`）整类丢弃条目：建筑/牌子从 Medium 起保留，散落模型（路灯、杆、集装箱）
  只有 **High** 起，公司/城市 POI 区域只有 **Extreme**。低于 High 时它还会丢掉所有"不上 UI 地图"的
  prefab 和道路——而隐蔽的场区正好是这一类，这条对停车业务比路灯更要命。
  先读数再动手：「地图数据」行末尾是 `建筑 N 段 / 点位 M`，设置 → 地图清单 会把每类明细和宿主
  当前保真度一起写进日志。
  如果清单里既没有 `Model` 也没有 `Buildings`，而实物就在眼前，那它是 prefab 自带几何——
  任何图层都画不出来（见 6.5、设计文档 §30）。

两个更早的坑，仍是最该先怀疑的：

1. **刹车变成油门**：宿主把 `aforward`/`abackward` 折进同一个 `acceleration` 桶做加权平均，
   再按符号分派。两个字段同时发 ⇒ 平均后变成半油门。正确做法是只发**一个带符号的字段**。
2. **`user_*` 是虚拟手柄的回声**：SDK 注入的量会以"玩家输入"的形式出现在 `user_*` 里。
   不要用它来判断"人类是否接管"，会误判。另外：我们当初**正是在 `legacy` 通路上**靠这个回声确认刹车
   进了游戏；换成 `memory` 通路后指令从另一块内存进去，哪个回显字段对应它还没重测过。与通路无关的硬
   证据是 `air=`。

设置文件：`%APPDATA%\ETS2LA\AutoParking.json`（含上次选的车位，重载插件不会丢）。宿主的踏板通路开关在
同一个目录的 `GameSettings.json`（`EnableModernOutputForPedals`），不在我们插件的设置里。
日志用的是 Spectre.Console markup，**消息里裸的 `[Tag]` 会被静默吞掉**。
